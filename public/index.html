Install the released package, then add FORGE to a project. Requires Node.js 22+ and Git.

# 1. install the CLI
npm install -g https://github.com/ansh44233/FORGE-ECC/releases/download/v4.0.0/forge-engineering-workbench-4.0.0.tgz
# 2. preview, then install with runtime hooks and the status line
cd your-project
forge install . --dry-run
forge install . --hooks --statusline
# 3. see where you stand
forge scorecard . && forge shield .

Memory

Carry the work forward.

Decisions, lessons and handoffs stay with the project — with the file or commit that backs them up — and reach every harness through MCP.

  • Layered. Project memory plus optional global memory across repositories.
  • Provenance. Every note records its source and evidence.
  • Safe. Credentials are rejected before anything is written.
  • Automatic. The latest handoff is injected when a new session starts.
# save a decision with evidence $ forge memory add . --kind decision \ --content "Validate API input with zod" \ --evidence src/schema.ts # leave a handoff for the next session $ forge memory handoff . \ --content "Login done; next: e2e tests" # search project + global memory $ forge memory search . --query "validation" # or from any agent over MCP forge_memory_search · forge_memory_add

FAQ

Questions before you begin.

What is FORGE?

An open-source agent harness. It installs specialist agents, skills, commands and rules into 10 coding tools, including Claude Code, Cursor, Codex, OpenCode, Gemini, Copilot, Windsurf, Kiro, Cline and Zed. It also guards risky actions with runtime hooks, scans agent configuration with Shield, learns approved project instincts, runs verified agent loops and checks pull requests through a GitHub App.

How is the verified loop different from letting an agent run?

FORGE decides when the work is done. Your agent never does. FORGE runs your checks itself after every iteration and saves a receipt. If the agent deletes or skips tests, loosens lint or type configs, or edits package scripts or CI, the loop stops for review instead of reporting a pass.

Does FORGE change my code?

No. forge install writes only FORGE-managed agent files and never overwrites your edits. The GitHub App proposes changes as pull requests you review.

What does the GitHub App read?

The file list, root manifests, commit subjects, pull request file lists and agent configuration files. It does not download or store your source code, and commands run only for collaborators with write access.

Can I use FORGE without an account?

Yes. The CLI, installer, Shield, hooks, memory and local dashboard work entirely on your machine. The GitHub App and hosted dashboard are optional.

Does a Shield score prove my setup is safe?

No. Shield is static analysis of known configuration locations. It helps you find and prioritize risk; it is not a certification.

Which tools does FORGE Guard run in?

Claude Code, Cursor, Codex and Gemini CLI, as native hooks installed by forge install --hooks. One policy in .forge/harness-hooks.json and one log (forge guard log) cover all four. Codex, Gemini and Cursor's file-read hook can't pause for approval, so where Claude Code would ask, FORGE blocks the action and tells the agent to get your go-ahead.

What is an agent race?

forge race gives the same goal to several agents, such as Claude Code, Codex and Gemini. Each works in its own git worktree, and FORGE ranks them using only its own check runs. An agent that deletes or skips tests can't win. Your working tree changes only when you run forge race pick.

How do I remove FORGE?

Run forge uninstall .. It removes only unmodified FORGE files and its managed blocks, and keeps anything you edited.
